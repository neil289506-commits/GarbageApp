# Garbage App

Garbage App is a Windows desktop application built with Electron and a native C++ addon. It intentionally consumes disk space and RAM for testing, demonstration, and stress-testing purposes.

> **Warning:** This application can consume large amounts of storage and memory. Use it only on a test machine or with data you can safely delete. Never target a drive containing important files.

## Features

- Write configurable amounts of data to a selected folder.
- Allocate memory through the native C++ addon.
- Allocate memory using hidden Electron renderer processes.
- Display progress while a waste operation is running.
- Release allocated memory and clean up temporary windows.

## Requirements

- Windows
- Node.js and npm
- Native build tools required by `node-gyp`
- An x64 environment

The native addon is built against Electron `33.2.0`.

## Installation

Clone the repository, install dependencies, and build the native addon:

```bash
npm run setup
```

This runs:

1. `npm install`
2. `npm run build:native`

## Run the application

Start the Electron application with:

```bash
npm start
```

Choose an operation from the navigation panel, configure the amount of data or memory, and start the operation. Use **Release memory** when you want to stop an active memory allocation.

## Build a Windows installer

Create a Windows NSIS installer with:

```bash
npm run dist
```

The installer is generated by `electron-builder`.

## Project structure

- `main.js` — Electron main process and IPC handlers.
- `preload.js` — Secure bridge between the renderer and main process.
- `renderer.js` — Main user-interface behavior.
- `index.html` — Main application interface.
- `native/` — C++ addon source and native build configuration.
- `waste.js`, `waste.html`, `waste-preload.js` — Hidden renderer used for Electron-based memory allocation.
- `package.json` — Development, setup, and distribution scripts.

## Safety and cleanup

The application writes files and allocates memory intentionally. Before running it:

- Save your work in other applications.
- Confirm the selected folder and requested amount.
- Keep sufficient free disk space and RAM available.
- Avoid running it on production systems.
- Delete generated files after testing if they are no longer needed.

If an allocation exceeds available memory, the application may fail or a renderer process may crash. Close the application and remove any generated files before trying again with a smaller amount.
